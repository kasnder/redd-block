# Manual edits inside `src-tauri/gen/android`

`gen/android` is generated by `tauri android init` and is committed to
the repo — Tauri does not regenerate the whole project on every build,
only if it's deleted and re-initialized. If that ever happens, redo the
manual edits below after running `tauri android init` again.

This is not a manifest of every generated file. Generated Kotlin glue,
resources, icons, and assets can be recreated by Tauri/icon generation;
the items below are the app-specific changes that are easy to lose.

1. **`app/src/main/AndroidManifest.xml`** — add
   `android:name="net.kollnig.reddblockandroid.plugin.BlockerApp"` and
   `android:directBootAware="true"` to the `<application>` tag. Without
   this, WorkManager re-enable/stop-session workers can't run before
   first unlock, and the device-protected-storage prefs migration in
   `BlockerApp.onCreate()` never runs.

2. **`app/src/main/java/net/kollnig/reddblockandroid/MainActivity.kt`** —
   the Tauri template only calls `enableEdgeToEdge()`; we additionally
   apply system-bar/IME insets as native padding on `android.R.id.content`
   (via `ViewCompat.setOnApplyWindowInsetsListener`). Without this, the
   webview draws underneath the status/navigation bars on Android 15+
   (edge-to-edge is enforced for targetSdk 35+) and CSS
   `env(safe-area-inset-*)` doesn't report them. The CSS side assumes
   this: `body.android` zeroes its safe-area padding (see styles.css).

3. **`app/build.gradle.kts`** — keep the Android identity and SDK levels
   aligned with the migrated Android app:

   - `namespace = "net.kollnig.reddblockandroid"`
   - `applicationId = "net.kollnig.reddblockandroid"`
   - `compileSdk = 36`
   - `minSdk = 26`
   - `targetSdk = 36`
   - `versionCode` / `versionName` should continue reading from
     `tauri.properties`, as generated by Tauri.

   See `tauri.android.conf.json` for the `identifier` — it must stay
   `net.kollnig.reddblockandroid` to preserve the AccessibilityService
   component name across the redd-block-android → Tauri migration (see
   `tauri-plugin-android-blocker/README` for why that matters).

   Keep the macOS Keychain-backed `playRelease` signing configuration and its
   environment-variable guard. `scripts/build-android-play.sh` supplies those
   variables only for Play Store builds; do not put the keystore or passwords in
   this generated project.

4. **`build.gradle.kts`** (project root) — the `allprojects { afterEvaluate { … } }`
   block that drops `consumerProguardFiles` entries pointing at files which do not
   exist. Tauri's published plugin crates (dialog, fs, opener, shell, and Tauri's
   own `mobile/android`) declare `consumer-rules.pro` without shipping it, and AGP
   fails `merge<Variant>ConsumerProguardFiles` on the missing path. Without this,
   **every release build fails** — `pnpm build:android` and
   `scripts/build-android-play.sh` both. Debug builds do not merge consumer rules,
   so `android-ci.yml` cannot catch its removal.

5. **`app/build.gradle.kts`** — `lint { checkReleaseBuilds = false }`.
   `lintVitalAnalyze<Flavor>Release` crashes inside Kotlin's FIR resolver while
   visiting the project's own `.gradle.kts` files (AGP 9.1.1 / Kotlin 2.2.21),
   aborting every release build. Revisit when either is upgraded: drop the flag,
   run `pnpm build:android`, and keep it out if the release build survives.

6. Do **not** hand-edit `tauri.settings.gradle` /
   `tauri.build.gradle.kts` / `tauri.properties` — these three are
   regenerated by the Tauri CLI on every `android dev`/`android build`
   from `Cargo.toml`'s dependency graph and `tauri.conf.json`. The
   `tauri-plugin-android-blocker` Gradle module is picked up
   automatically this way because its `Cargo.toml` sets
   `links = "tauri-plugin-android-blocker"` and its `build.rs` calls
   `.android_path("android")` — no manual `settings.gradle` include is
   needed.
